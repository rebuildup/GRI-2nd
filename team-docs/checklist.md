## 2. 必須確認事項

各班で、次の項目を確認してください。

### A. V1 から V2 への変更

- [x] V1 ではメインループから`ledexec()`を呼び出していたことが説明されている。
- [x] V2 では LED の点灯・消灯の判断と出力を`led_handler()`へ移すことが説明されている。
- [x] `init_timer0(COUNT_100MSEC, led_handler)`によって関数を登録することが示されている。
- [ ] メインループに残す処理（`led()`による設定、モータ処理など）が明確になっている。
- [ ] V2 で不要になる旧`ledexec()`の宣言・定義・呼び出しの扱いが説明されている。

### B. 初期化・通常動作・終了処理

- [ ] LED モジュールや初期状態の設定を完了してからタイマを開始する。

- [ ] 最初の点灯がどのタイミングで行われるか説明されている。

- [ ] `led_handler()`がタイマから呼び出されたとき、どのような判断と出力を行うか明確になっている。

- [ ] プログラム終了時にタイマを停止し、モータ停止、LED・数値 LED 消灯を行う。

- [ ] プログラムを再実行した場合にも、所定の初期状態から動作する。

### C. LED の動作仕様

- [ ] `-N`、`-F`、`-B`、`-DEBUG1` の機能と既定値が説明されている。

- [ ] 点滅モード 0〜3 の動作が説明されている。

- [ ] 点灯周期と点灯・消灯の反転間隔を区別している。

- [ ] LED のビット対応とアクティブ Low の出力について説明されている。

- [ ] 50ms など通常の検証範囲外の入力に対し、どのように対応するか決めている。特に割込み処理内でゼロ除算が発生しないこと。

### D. 本文と図の整合性

- [ ] モジュール関連図で、V2 の関数構成が分かる。

- [ ] PAD 図に、V2 で変更した判断・処理が反映されている。

- [ ] シーケンス図では、timer0_handler から led_handler が呼び出される関係が分かる。

- [ ] 本文、関数仕様、PAD 図、シーケンス図で、関数名や呼び出し順序が一致している。

- [ ] V1 から変更しなかった図や処理についても、その理由が説明されている。

図があるだけでは十分ではありません。特に変更した処理については、図と文章の両方で説明してください。
